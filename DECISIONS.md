# Architecture decisions

## Milestones 0 and 1

- **One SvelteKit application.** TypeScript, server-rendered public pages and authenticated JSON endpoints share the same repository functions. Plain text is escaped by Svelte and preserves line breaks. Markdown is deferred.
- **Local-first infrastructure.** SQLite and filesystem storage make the full workflow available with Node alone. The production-oriented adapters use parameterized SQL Server queries and Azure Blob Storage. The same relational core and repository work across both databases. The SQLite migration runs automatically. The SQL Server migration runs separately. Sources, tags, visits history and publication audit tables will be introduced with their workflows. Private notes can hold research and visit details in this slice.
- **Identity.** Local development uses an explicit passphrase fixture with an expiring signed HttpOnly cookie. The fixture is disabled in production builds. Production mode delegates sign-in to Azure Container Apps Easy Auth and checks the tenant and exact Entra object ID on every owner route. Enable this mode only behind ingress that strips client-supplied identity headers and injects validated claims. Private mutations require a same-origin request.
- **Capture.** The Add button creates a durable untitled record before showing the camera and gallery controls. Text autosaves after a short debounce, reports errors and keeps a tab-local recovery copy until acknowledged. Revision checks surface concurrent edits. Uploads are sequential per tab so photo order follows selection. Upload IDs make retries safe after a lost response. File objects remain in the open tab until saved or dismissed.
- **Media.** Server-side Sharp decoding validates still JPEG, PNG, WebP and AVIF images, with size and pixel limits. HEIC camera settings may need JPEG mode. The app retains private originals and stores separate metadata-free JPEG display and thumbnail variants under keys derived from the record and photo IDs. A database row becomes visible after all variants are stored. Removed or interrupted uploads may leave private files for later recovery or cleanup. The public media route checks the current record and photo visibility on every request. Direct-to-Blob SAS, browser-side compression and background upload after closing the tab are deferred.
- **Publication.** The vertical slice includes a small publish/unpublish action to exercise the public page with the owner’s own content. First publish creates a readable prefix with a UUID suffix. Later title edits keep the URL. Published metadata changes go live on autosave. Approved photos need alt text. A deliberate waiver permits publication without photos. The public query selects explicit columns and excludes all original media and private fields.
- **Mobile.** The first capture screen has optional name, area and note fields, separate gallery and rear-camera inputs, a sticky save action and immediate local previews. The manifest supplies home-screen icons. Device-specific installation, offline features, geolocation and the share target are deferred.
- **Milestone boundaries.** Public directory, map, SEO expansion, Azure rollout and export follow in Milestone 2. Deeper capture polish, sources and visits follow in Milestone 3. The caption is editable and copyable and each photo has a JPEG download. Instagram account integration belongs to Milestone 4.
- **Instagram handoff.** The owner editor passes approved JPEGs in editor order through the device share menu and provides a copyable caption built from the website description, city and country. Preparing the files before the share tap preserves the browser's required user activation. Instagram owns account selection, audience selection and final publication. Individual JPEG downloads cover browsers or share targets without multi-file support.
