# Architecture decisions

- **Research images remain private references.** Migration 008 adds a JSON image list to potential records. Each item stores a direct HTTPS image URL, source page, credit and permission notes. The owner can add/remove links and move an image first to choose its thumbnail; saves retain revision protection. Images load directly in the browser with no referrer and are not copied to Blob Storage, proxied through the server, published, or passed to Instagram. Database backups preserve the links and provenance, not external image files. A reviewed starter dataset covers all 55 current candidates; a repeatable owner action appends missing URLs without replacing existing images or their order. Broken remote images fall back to a neutral list placeholder.
- **Owner list thumbnails use draft photos.** One ranked SQL query picks the selected cover when it exists, otherwise the first photo by position and ID, for each statue. Thumbnails use the existing authenticated media endpoint and never change public photo permissions or publication snapshots. The shared private list component covers workspace, inbox and all-statue records. Potential records use their first research image.

- **Private catalogue map.** Leaflet is bundled locally and loaded only in the browser. OpenStreetMap supplies attributed map tiles; only the visible map tiles are requested, with ordinary browser caching and origin referrers. Saved coordinates take priority. A server-side, sourced snapshot supplies labelled approximate postcode centres/areas or researched locations for the initial entries without coordinates; this never updates saved pin coordinates or marks a pin checked. Fallbacks are invalidated when the record's address, city or country changes. Search and status filters drive both list and map; nearby markers group by screen-space cells with all entries accessible in the popup. New entries without coordinates stay visible in the list and a missing-coordinate summary. No runtime geocoding, API key, new Azure service or database migration is needed.

- **Potential statues are independent private records.** Migration 007 introduces `dog_statues.potential_statues` (SQLite equivalent locally), with no relationship to publication or Instagram state. Owner routes reuse the existing authentication, same-origin mutation checks and Maps resolver. Explicit saves use revision checks to protect against stale edits; archive retains research without making it an active visit lead. This shares existing database backups and adds no Azure service.
- **Curated research imports preserve provenance.** Stable IDs merge seven initial London overlaps with the owner's 47-row CSV and make repeated imports safe without overwriting owner edits. The original CSV and numbered sourced story findings remain in `research/`; only the server imports the combined dataset. Original pin precision and uncertain/current-location caveats remain in private notes, and supplied coordinates are never marked independently checked. Separate installed works remain separate even where subjects or addresses match. Research does not become public copy automatically.

- **Private publication snapshots.** Publishing stores only the public fields and approved photo metadata in the statue row. Public pages, the directory, RSS and photo access use that saved version. Preview uses the same page component with authenticated photo URLs. Private research and drafts stay in the existing statue record. The migration captures current published content before the app changes its read path.
- **Sources stay private.** The owner requested private research sources for this release. Source notes, checked dates, sculptor, unveiling details and plaque transcriptions are available in the editor and excluded from public snapshots.

## Milestones 0 and 1

- **One SvelteKit application.** TypeScript, server-rendered public pages and authenticated JSON endpoints share the same repository functions. Plain text is escaped by Svelte and preserves line breaks. Markdown is deferred.
- **Local-first infrastructure.** SQLite and filesystem storage make the full workflow available with Node alone. The production-oriented adapters use parameterized SQL Server queries and Azure Blob Storage. The same relational core and repository work across both databases. The SQLite migration runs automatically. The SQL Server migration runs separately. Sources, tags, visits history and publication audit tables will be introduced with their workflows. Private notes can hold research and visit details in this slice.
- **Identity.** Local development uses an explicit passphrase fixture with an expiring signed HttpOnly cookie. The fixture is disabled in production builds. Production mode delegates sign-in to Azure Container Apps Easy Auth and checks the tenant and exact Entra object ID on every owner route. Enable this mode only behind ingress that strips client-supplied identity headers and injects validated claims. Private mutations require a same-origin request.
- **Capture.** The Add button creates a durable untitled record before showing the camera and gallery controls. Text autosaves after a short debounce, reports errors and keeps a tab-local recovery copy until acknowledged. Revision checks surface concurrent edits. Uploads are sequential per tab so photo order follows selection. Upload IDs make retries safe after a lost response. File objects remain in the open tab until saved or dismissed.
- **Media.** Server-side Sharp decoding validates still JPEG, PNG, WebP and AVIF images, with size and pixel limits. HEIC camera settings may need JPEG mode. The app retains private originals and stores separate metadata-free JPEG display and thumbnail variants under keys derived from the record and photo IDs. A database row becomes visible after all variants are stored. Removed or interrupted uploads may leave private files for later recovery or cleanup. The public media route checks the current record and photo visibility on every request. Direct-to-Blob SAS, browser-side compression and background upload after closing the tab are deferred.
- **Publication.** The vertical slice includes a small publish/unpublish action to exercise the public page with the owner’s own content. First publish creates a readable prefix with a UUID suffix. Later title edits keep the URL. Published metadata changes go live on autosave. Approved photos need alt text. A deliberate waiver permits publication without photos. The public query selects explicit columns and excludes all original media and private fields.
- **Mobile.** The first capture screen has optional name, area and note fields, separate gallery and rear-camera inputs, a sticky save action and immediate local previews. The manifest supplies home-screen icons. Device-specific installation, offline features, geolocation and the share target are deferred.
- **Milestone boundaries.** Public directory, map, SEO expansion, Azure rollout and export follow in Milestone 2. Deeper capture polish, sources and visits follow in Milestone 3. The caption is editable and copyable and each photo has a JPEG download. Instagram account integration belongs to Milestone 4.
- **Instagram handoff.** The owner editor passes approved JPEGs in editor order through the device share menu and provides a copyable caption built from the website description, city and country. Preparing the files before the share tap preserves the browser's required user activation. Instagram owns account selection, audience selection and final publication. Individual JPEG downloads cover browsers or share targets without multi-file support.
- **Direct Instagram publishing.** The Atlas verifies the configured Dog Statues account before creating Meta containers and requires a separate public-post confirmation. The preview uses the website description and location by default, as requested. Meta fetches square, padded JPEG derivatives through short-lived signed URLs. The database stores publication state independently from website publication and blocks a second post while the first has an uncertain or successful outcome.
